阶段 1 · 去掉主机开销

StepState：元数据一次上传

每步的小数据打成一包，一次 H2D。

本步目标把每一步 kernel 需要的“小数据”（token id、位置、KV 的 slot、块表、每条序列的长度、温度、随机种子）打成一个包，每步只上传一次。这一步先让 embedding 从包里读 ids；包里其余字段后面几步陆续用上。

原理

kernel 除了张量还需要什么

一步前向里，各个 kernel 需要一些随步变化的小数据：

数据谁用现在放在哪
token idembedding第 03 步的 ids_dev
每个 token 的位置RoPEop_params[2] 里的起点，kernel 里现算 start + s
每个 token 写进 KV 的哪个槽写 KVhost 上逐个算，逐个 memcpy
块表注意力host 上的 page_table，每层 cudaMalloc + H2D + cudaFree
上下文长度注意力函数参数 total_cached
每条序列最后一个 token 的行号gather_last（第 08 步）还没有
温度、随机种子GPU 采样（第 09 步）还没有

这些数据加起来很小：S1 的 decode 步不到 300 字节，512 token 的 prefill 约 6 KB。分散着传，每传一次就是一次 CUDA API 调用；打成一包，每步就只有一次 H2D。

为什么它们不能当函数参数传

单序列时，“位置起点”“上下文长度”这些是标量，当 kernel 参数传没问题。多条序列一起跑时（第 19 步），每条序列的起点和长度都不同，必须是数组；数组要 kernel 读，就得在显存里。现在就按数组的形式设计，后面批处理不用返工。

第 17 步的 CUDA Graph 还有一个更硬的要求：录制时 kernel 的参数会被固化，回放时改不了。所以随步变化的东西只能放在显存里，每步更新显存内容，而指针保持不变。

    /// 按最大规模切一块常驻的元数据缓冲。取代第 03 步的 ids_dev。
    fn allocMeta(self: *Self) !void {
        const lay = Layout.init(self.max_seq, MAX_SEQS, self.max_seq / PF_TILE + MAX_SEQS, self.max_blocks);
        const dev_type = self.input_tensor.device_type;
        const dp = self.memory_manager.get(dev_type, 0) orelse return error.NoDevicePools;
        const pool = &(dp.activation orelse return error.NoActivationPool);
        const blk = try pool.allocate(lay.total, pools.POOL_ALIGN);
        pool.markPersistent();
        self.meta_dev = @intFromPtr(blk.ptr);
        if (opts.have_cuda and dev_type == .CUDA) {
            self.meta_host = @ptrCast(cuda.cuda_host_alloc(lay.total) orelse return error.PinnedAllocFailed);
        } else {
            self.meta_host = blk.ptr; // CPU 的池 host 可寻址, 直接往里写
        }
    }

    fn i32At(self: *Self, off: usize) [*]i32 {
        return @ptrCast(@alignCast(self.meta_host + off));
    }
    fn f32At(self: *Self, off: usize) [*]f32 {
        return @ptrCast(@alignCast(self.meta_host + off));
    }
    fn devAt(self: *const Self, off: usize) ?*anyopaque {
        return @ptrFromInt(self.meta_dev + off);
    }

    fn uploadMeta(self: *Self, bytes: usize) void {
        if (opts.have_cuda and self.input_tensor.device_type == .CUDA) {
            cuda.cuda_h2d(self.devAt(0), self.meta_host, bytes); // 第 07 步换成异步
        }
    }

                    tile += 1;
                }

        var s = entries.len;

            ids[t] = 0;
            pos[t] = 0;
            slots[t] = -1;
            t += 1;

            ctx[s] = 0;
            last[s] = @intCast(t - 1);
            temps[s] = 0;
            @memset((bt + s * mb)[0..mb], 0);
        }

常见错误

现象原因和处理
incorrect alignment panic 在 i32AtLayout 的各段偏移必须是 4 的倍数。seed 占 8 字节，后面全是 4 字节一项，照抄 lab 的 Layout.init 不会错；自己改顺序时注意。
OutOfPoolMemory（activation 池）元数据缓冲按最大规模切，max_seq = 1024 时约 13 KB，不该撑爆。多半是 allocMeta 被调了多次，或 markPersistent 之后又有人 reset 到 0。
decode 第二步起输出乱emits() 判断的是 q_start + q_len == seq.len()。先 append 新 token 再构造 Entry，顺序反了就会把上一个 token 再喂一遍。
RoPE 位置错（输出语无伦次）这一步 RoPE 还读 op_params[2]，setRopeStart 必须在 forward 之前调，值是本步第一个 token 的位置。

检查点

  • greedy 输出和基线逐 token 相同
  • forward 的参数是 []const Entry，generate 里用 Sequence 存 token
  • input_tensor.data 指向元数据包里的 ids 段
