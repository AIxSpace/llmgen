阶段 3 · kernel

Linear：GEMV + cuBLAS

decode 读权重的带宽，决定 ITL 的下限。

本步目标Linear 分两条路：decode 的小批（M ≤ 2）走自写的 GEMV，其余走 cuBLAS 的 bf16 tensor core GEMM。decode 的时间有七成花在这里。

原理

decode 的 Linear 是在“读权重”

decode 时每个 Linear 的输入只有一行：y[N] = W[N, K] · x[K]，矩阵乘向量（GEMV）。计算量很小（每个权重元素一次乘加），但每个权重都得读一遍。

Qwen3-0.6B 每步要读的权重：28 层 × 7 个 Linear，加上 lm_head 的 297 MB，共 1.19 GB。按 3090 的显存带宽，下限是 1.27 ms。目标 lab 的 ITL 是 2.449 ms，其中约 1.5 ms 就是在读权重。

所以 decode 的 Linear 只有一个指标：读权重的带宽。nsys 里融合版 S1 的 kernel 时间，GEMV 一项占 69.7% nsys 实测。

起点：全交给 cuBLAS

src/backend/cuda/linear.cu 起点（你现在的代码）
// 对照 LinearImpl<Device::CUDA>::execute(Tensor* out, int32_t dev_id) 的 cuBLAS 分支
//   x: [M, K]  w: [N, K](GGUF 行主, dims = [K, N])  out: [M, N]
extern "C" void cuda_linear(void *out, const void *x, const void *w, int dtype, int wdtype,
                            int64_t M, int64_t K, int64_t N, int dev_id) {
    cudaSetDevice(dev_id);

    const void* A = w;
    if (wdtype != dtype) {
        if (dtype != GT_F32) {
            fprintf(stderr, "Linear: mixed dtype only supports f32 activations\n");
            return;
        }
        long wn = (long)N * K;
        float* wf32 = dequant_scratch(wn);
        constexpr int threads = 256;
        dequant_weight_kernel<<<(unsigned)((wn + threads - 1) / threads), threads>>>(wf32, w, wdtype, wn);
        A = wf32;
    }

    cudaDataType_t cdtype = to_cuda_dtype(dtype);
    const float alpha = 1.0f, beta = 0.0f;
    const void* Bptr = x;
    void*       C = out;
    const int ldb = K, ldc = N;
    const long long strideA = 0;
    const long long strideB = M * K;
    const long long strideC = M * N;

    cublasHandle_t handle = CublasHandlePool::get();
    cublasGemmStridedBatchedEx(
        handle,
        CUBLAS_OP_T, CUBLAS_OP_N,
        N, M, K,
        &alpha,
        A, cdtype, K, strideA,
        Bptr, cdtype, ldb, strideB,
        &beta,
        C, cdtype, ldc, strideC,
        1,
        CUBLAS_COMPUTE_32F,
        CUBLAS_GEMM_DEFAULT_TENSOR_OP
    );

    cudaError_t err = cudaGetLastError();
    if (err != cudaSuccess) {
        fprintf(stderr, "Linear GEMM launch failed: %s\n", cudaGetErrorString(err));
    }
}

激活和权重都是 bf16，直接交给 cublasGemmStridedBatchedEx。这对 prefill（M 很大）是对的选择，对 M = 1 则未必：cuBLAS 按通用 GEMM 的思路挑 kernel，有分块、有启动开销。

自写 GEMV 的线程映射

一个 warp 负责输出的一行（一个 n）：32 个 lane 交错读权重的第 n 行，每个 lane 一次读一个 bf16x8，累加自己的部分和，最后 warp_sum。

k=0,32,64,96
lane 1
k=1,33,65,97
lane 2
…
lane 29
lane 30
lane 31
k=31,63,95,127
← W 的第 n 行，K = 1024 = 128 个 bf16x8
一个 warp 顺序扫过权重的一行（2 KB 连续显存）。8 个 warp 一个 block，处理 8 行。

M = 2 时，同一次读出来的权重和两行 x 各乘一遍：权重只读一次。这就是模板参数 M 的作用。

backend/cuda/linear.cu lab 参考（3090 实测过）
// lab: module-serving-unfused -- linear.cu: y[M,N] = x[M,K] · W[N,K]^T
//
// 对照 module-style linear.cu: 那里每次调用都把 BF16 权重反量化成 f32 临时显存再 cublasSgemm(无 tensor core).
// 这里权重常驻显存且保持 BF16, 分两条路:
//   M ≤ SV_GEMV_MAX_M(decode 极小批): 自写 GEMV —— 一个 warp 负责一行输出, 16B 向量化顺序读权重行, M 个输入行复用同一次权重读取.
//     decode 是纯带宽受限(每步把 1.2GB 权重读一遍), M=1~2 时它比 cuBLAS 快 ~10%(cuda-course 第 05 课).
//   其余: cuBLAS GemmEx(A/B=BF16, C=BF16 或 f32, compute=32F) → tensor core.
//     M 变大后 GEMV 每个 lane 要为 M 行各解包一次 x、各累加一份, 计算和寄存器压力上来:
//     M=8 时 lm_head 只剩 487 GB/s, cuBLAS 仍有 864 GB/s; 而 CUDA Graph 的 decode 桶 1,2,4,8 会把 5~7 条序列补到 8,
//     所以阈值卡在 cuBLAS 反超之前. cuBLAS 用 cuda_init 里的固定 workspace, 照样能录进 CUDA Graph.
//
// 行主 → 列主换算(cuBLAS 路): y 行主 [M,N] == 列主 [N,M]
//   C_cm[N,M] = op(W)^T[N,K] · op(x)[K,M];  W 行主 [N,K] = 列主 [K,N] → OP_T, lda=K; x 行主 [M,K] = 列主 [K,M] → OP_N, ldb=K
#include "cuda_common.cuh"

#define GEMV_WARPS 8
#ifndef SV_GEMV_MAX_M
#define SV_GEMV_MAX_M 2 // 3090 实测见 README.md 的「GEMV 阈值」一节
#endif

template <int M, bool OUT_F32>
__global__ void __launch_bounds__(GEMV_WARPS * 32) gemv_kernel(void *y, const bf16x8 *x, const bf16x8 *w, int N, int K8) {
    const int lane = threadIdx.x & 31;
    const int n = blockIdx.x * GEMV_WARPS + (threadIdx.x >> 5);
    if (n >= N) return; // 整个 warp 一起退出(n 在 warp 内一致), 不影响下面的 warp shuffle
    const bf16x8 *wr = w + (long)n * K8;
    float acc[M];
#pragma unroll
    for (int m = 0; m < M; ++m) acc[m] = 0.f;
#pragma unroll 4
    for (int k = lane; k < K8; k += 32) {
        float wf[8];
        unpack8(wr[k], wf);
#pragma unroll
        for (int m = 0; m < M; ++m) {
            float xf[8];
            unpack8(x[(long)m * K8 + k], xf);
#pragma unroll
            for (int e = 0; e < 8; ++e) acc[m] += wf[e] * xf[e];
        }
    }
#pragma unroll
    for (int m = 0; m < M; ++m) {
        float v = warp_sum(acc[m]);
        if (lane == 0) {
            if (OUT_F32) ((float *)y)[(long)m * N + n] = v;
            else ((bf16 *)y)[(long)m * N + n] = f2bf(v);
        }
    }
}

template <int M>
static void launch_gemv(void *y, int y_f32, const cuda_bf16_t *x, const cuda_bf16_t *w, int N, int K) {
    dim3 grid((N + GEMV_WARPS - 1) / GEMV_WARPS);
    if (y_f32)
        gemv_kernel<M, true><<<grid, GEMV_WARPS * 32, 0, g_cuda_stream>>>(y, (const bf16x8 *)x, (const bf16x8 *)w, N, K / 8);
    else
        gemv_kernel<M, false><<<grid, GEMV_WARPS * 32, 0, g_cuda_stream>>>(y, (const bf16x8 *)x, (const bf16x8 *)w, N, K / 8);
}

// 环境变量 SV_GEMV_MAX_M 覆盖编译期默认值(0 = 全走 cuBLAS, 最大 8), 首次调用读一次
static int gemv_max_m() {
    static const int m = [] {
        int v = cuda_env_int("SV_GEMV_MAX_M", SV_GEMV_MAX_M);
        v = v < 0 ? 0 : (v > 8 ? 8 : v);
        if (v != SV_GEMV_MAX_M) fprintf(stderr, "[serve] 回退开关 SV_GEMV_MAX_M=%d\n", v);
        return v;
    }();
    return m;
}

extern "C" void cuda_linear(void *y, int y_f32, const cuda_bf16_t *x, const cuda_bf16_t *w, int M, int N, int K) {
    if (M <= 0) return;
    if (M <= gemv_max_m() && K % 8 == 0) {
        switch (M) {
            case 1: launch_gemv<1>(y, y_f32, x, w, N, K); return;
            case 2: launch_gemv<2>(y, y_f32, x, w, N, K); return;
            case 3: launch_gemv<3>(y, y_f32, x, w, N, K); return;
            case 4: launch_gemv<4>(y, y_f32, x, w, N, K); return;
            case 5: launch_gemv<5>(y, y_f32, x, w, N, K); return;
            case 6: launch_gemv<6>(y, y_f32, x, w, N, K); return;
            case 7: launch_gemv<7>(y, y_f32, x, w, N, K); return;
            case 8: launch_gemv<8>(y, y_f32, x, w, N, K); return;
        }
    }
    const float alpha = 1.f, beta = 0.f;
    cublasStatus_t st = cublasGemmEx(g_cublas, CUBLAS_OP_T, CUBLAS_OP_N,
                                     N, M, K,
                                     &alpha,
                                     w, CUDA_R_16BF, K,
                                     x, CUDA_R_16BF, K,
                                     &beta,
                                     y, y_f32 ? CUDA_R_32F : CUDA_R_16BF, N,
                                     CUBLAS_COMPUTE_32F, CUBLAS_GEMM_DEFAULT);
    if (st != CUBLAS_STATUS_SUCCESS) fprintf(stderr, "[serve] cublasGemmEx failed: %d (M=%d N=%d K=%d)\n", (int)st, M, N, K);
}

M = 1、2 时自写 GEMV 比 cuBLAS 快约 12%（12 MB 的矩阵）；M = 4 起 cuBLAS 反超，M = 8 时 GEMV 只剩 407 GB/s。原因是 GEMV 的内层循环要为每个 M 各解包一次 x、各维护一个累加器，寄存器和计算压力随 M 线性增长；cuBLAS 的 kernel 不受影响。

阈值定在 2 还有一个原因：第 17 步的 CUDA Graph 按批大小分桶（1, 2, 4, 8, 16, …），5–7 条序列会被补到 8。阈值要卡在 cuBLAS 反超之前。

常见错误

现象原因和处理
输出全错参数顺序。新接口是 (M, N, K)，旧的是 (M, K, N)。N 是输出维 = w.dims[0]，K 是输入维 = w.dims[1]。
cublasGemmEx failed: 1（NOT_INITIALIZED）g_cublas 没建。cuda_init 里的 cublasCreate 要在第一次 Linear 之前。
prefill 时 cublasGemmEx failed: 3（ALLOC_FAILED）固定 workspace 不够。32 MB 对 8192 × 3072 的 GEMM 是够的（lab 实测）；自己调大了 max_seq 就相应加大。
[serve] 回退开关 SV_GEMV_MAX_M=0 没打印环境变量在第一次调用 cuda_linear 时读一次。确认它传进了进程（make 会继承环境）。
