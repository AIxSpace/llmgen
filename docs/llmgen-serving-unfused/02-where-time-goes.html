阶段 0 · 先能量

64 ms 去哪了

读两份账本：算子 profiler 和 nsys。先看清楚再动手。

本步目标弄清起点每个 token 的 64.63 ms 花在哪。这一步不改代码，只学会读两份账本：llmgen 自带的算子 profiler，和 nsys 的 CUDA API 统计。

原理

GPU 推理的时间分三类

host
填参数launch等同步launch等同步malloc小拷贝freelaunch等同步
GPU
kernel A空闲kernel B空闲 …kernel C
起点的时间线：GPU 干一小会儿，然后等 host 发下一个命令。
  1. kernel 真正在算：GEMV 读权重、注意力读 KV。优化手段是改 kernel（阶段 3）。
  2. CUDA API 的固定开销：每次 launch、malloc、free、memcpy、sync 各几微秒到几十微秒，和数据量无关。次数多了就是大头。
  3. host 自己在算：CPU 上的 embedding、采样、调度。

decode 是带宽受限的：每步要把 1.2 GB 权重读一遍，3090 显存带宽约 900 GB/s，下限就是 1.3 ms 左右。目标 lab 的 ITL 2.449 ms 已经离这个下限不远。起点的 64.63 ms 里绝大部分属于第 2、3 类。

起点里的三处固定开销

第一处：每个算子后同步。

src/executor.zig 起点（你现在的代码）
    fn executorTensor(self: *Self, tensor: *Tensor) !void {
        if (isViewOp(tensor.op_type)) {
            return executeView(tensor); // 内部转换处理
        }

        const device_id = self.graph_scheduler.deviceIdForLayer(tensor.layer_id) orelse 0;

        try self.allocateOutput(tensor, device_id);

        // 需要分析时开启，不要影响指标 metrics 评估
        if (self.profiler.enabled) {
            var timer = try std.time.Timer.start();
            try dispatchKernel(tensor, @intCast(device_id));
            if (opts.have_cuda and tensor.device_type != .CPU) {
                // 这里目前是同步操作，所以 OpProfiler 能算准
                cuda.CudaContext.instance().sync(); // cuda 同步操作
            }
            const ns = timer.read();
            const ctx: u64 = @intCast(self.seq_pos + self.cur_tokens); // forward 期间 seq_pos 还没更新
            self.profiler.record(
                tensor.op_type,
                tensor.device_type,
                ns,
                profiler.opCost(tensor, ctx),
            );
        } else {
            try dispatchKernel(tensor, @intCast(device_id));
            if (opts.have_cuda and tensor.device_type != .CPU) {
                cuda.CudaContext.instance().sync(); // cuda 同步操作
            }
        }
    }

每层 22 个 kernel（norm、q/k/v、3 个拆头 permute、q/k norm、q/k rope、attn、合头 permute、o、两个残差、ffn norm、gate/up、silu、mul、down），28 层共 616 个，每个后面一次 cudaDeviceSynchronize。

第二处：写 KV 逐 token、逐头拷贝。

src/memory/page_atten.zig · appendKVFromTensor 起点（你现在的代码）
        var seq_idx: i32 = 0;
        while (seq_idx < seq_len) : (seq_idx += 1) {
            const global_pos = prev_cached + seq_idx;

            const logical_block: usize = @intCast(@divFloor(global_pos, PAGE_BLOCK_SIZE));
            const offset_in_block: usize = @intCast(@mod(global_pos, PAGE_BLOCK_SIZE));

            const entry = layer_state.page_table.items[logical_block];
            const nk: usize = @intCast(n_kv_heads);
            const kv_base = offset_in_block * nk * @as(usize, @intCast(head_dim)) * elem_size;
            const k_blk = layer_state.k_pool.blockData(entry.k_block_id);
            const v_blk = layer_state.v_pool.blockData(entry.v_block_id);

            var h: usize = 0;
            while (h < nk) : (h += 1) {
                const src_offset = h * head_stride_bytes + @as(usize, @intCast(seq_idx)) * head_dim_bytes; // 输入 head-major
                const dst_offset = kv_base + h * head_dim_bytes; // 块内 token-major:[token][kv_head][hd]

                const device_type = self.pool.getDeviceType(); // pools.zig 里把 getDeviceType 改成 pub
                deviceMemcpy(k_blk[dst_offset .. dst_offset + head_dim_bytes], k_data[src_offset .. src_offset + head_dim_bytes], device_type);
                deviceMemcpy(v_blk[dst_offset .. dst_offset + head_dim_bytes], v_data[src_offset .. src_offset + head_dim_bytes], device_type);
            }
        }
    }

decode 每步每层：8 个 KV 头 × (K + V) = 16 次 cudaMemcpy（D2D），28 层共 448 次。每次只搬 256 字节。

第三处：页表每层重新上传。

src/backend/cuda/attention.cu 起点（你现在的代码）
static void upload_page_table(const int32_t* h_page_k_ids, const int32_t* h_page_v_ids, int32_t num_blocks,
                              int32_t** d_page_k_ids, int32_t** d_page_v_ids) {
    cudaMalloc(d_page_k_ids, num_blocks * sizeof(int32_t));
    cudaMalloc(d_page_v_ids, num_blocks * sizeof(int32_t));
    cudaMemcpy(*d_page_k_ids, h_page_k_ids, num_blocks * sizeof(int32_t), cudaMemcpyHostToDevice);
    cudaMemcpy(*d_page_v_ids, h_page_v_ids, num_blocks * sizeof(int32_t), cudaMemcpyHostToDevice);
}

每层 2 次 cudaMalloc、2 次 H2D cudaMemcpy、2 次 cudaFree，28 层共 56 / 56 / 56 次。cudaFree 还会隐式等待设备空闲。

动手量一遍

1算子级 profile

终端 命令
LLMGEN_METRICS=1 LLMGEN_PROFILE=1 make llmgen-cuda 2>&1 | tee /tmp/llmgen-profile.txt

看 decode 阶段的表，关注三件事：

  • 哪类算子占比最高。预期是 LINEAR 和 PAGED_ATTN。
  • PAGED_ATTN 的平均耗时。它包含了 appendKVFromTensor 的 16 次拷贝和页表上传，kernel 本身只占一小部分。
  • “框架开销”一行（printOverhead 打的）。forward 总时间减去各算子时间之和。
profile 模式下的吞吐不能当成绩LLMGEN_PROFILE=1 要在每个算子后同步才能量准。起点本来就每个算子同步，所以现在两种模式差不多；第 07 步之后，profile 模式会明显更慢，报吞吐一律用不带 PROFILE 的运行。

2nsys 看 CUDA API

终端 命令
# nsys 在 CUDA toolkit 里(/usr/local/cuda/bin/nsys)。--trace=cuda 只抓 CUDA API 和 kernel。
LLMGEN_MODEL=/home/deploy/qwen/qwen306b/models/Qwen3-0.6B-BF16.gguf \
LD_LIBRARY_PATH=/usr/local/cuda/lib64 \
nsys profile --trace=cuda -o /tmp/llmgen-start ./zig-out/bin/llminfer

# 三张表:CUDA API 耗时、kernel 耗时、memcpy 耗时
nsys stats --report cuda_api_sum --report cuda_gpu_kern_sum --report cuda_gpu_mem_time_sum /tmp/llmgen-start.nsys-rep

把你的 cuda_api_sum 和上面 module-style 那张表并排看。预期起点的形状介于两者之间：权重和激活已经常驻显存，所以 cudaMemcpy 的平均耗时会比 108 µs 小很多（搬的是 256 字节而不是整块权重），但次数仍然是每步五百多次。

常见错误

现象原因和处理
nsys: command not found在 /usr/local/cuda/bin/ 下，加进 PATH。没装的话 apt install cuda-nsight-systems-12-6（版本号跟 toolkit 走）。
nsys 报告里 kernel 名字一长串模板实例化后的全名。nsys stats 默认截断，够认了。
profile 各算子之和比 forward 时间小很多差值就是框架开销。起点里 appendKVFromTensor 算在 PAGED_ATTN 里，不在这个差值里。
