要追的差距

这份教程带你把 src/llmgen 一步步改到 module-serving-unfused 的性能水平。目标 lab 去掉了算子融合， 图的粒度和 llmgen 现在一样（每个细粒度模块一个节点），所以这条路上不需要做融合：要补的全在执行层、kernel 和批处理。

差距主要不在算子 起点每个 token 要 64.63 ms，其中 forward 占 93.5%。但这段时间里 GPU 大部分时候在等主机： 每个算子后同步一次、每层写 KV 做十几次小拷贝、每层上传一次页表。所以顺序是先去掉主机开销（阶段 1），再裁掉多余计算（阶段 2），然后才轮到 kernel（阶段 3）。

CPU 支线

主线只讲 CUDA 路径。想让 CPU 后端全程保持可用（mac 上开发、没有 GPU 的机器上演示、给 CUDA 当对拍参考），就在做主线的同时做这条支线：

#页面对应主线内容
C1一套执行层两个后端全程CPU 和 CUDA 只在哪几处不同；每一步 CPU 要做什么的对照表
C2并行与 SIMD 工具开始之前bf16 直读、@Vector 点积、fork-join 线程团队
C3布局相关的算子03、05、06、08、09embedding、rope、attention、gather_last、sample
C4计算类算子10、11、12、15Linear、add / mul / silu、RMSNorm、CPU 单测
C5执行层与命令行16–22KV 预算、加载、--device、CPU / CUDA 逐 token 对拍

建议的顺序：开始主线之前先做 C2 和 C4 的 Linear（否则 CPU 上一次前向要十几秒，每步验证都要等）；之后主线做到哪一步，就按那一步“CPU 同步”小节的链接去做对应的一节。完整的对照表在 C1。

怎么读每一页

每页结构固定：目标 → 原理 → 起点代码哪里慢 → 分步改动 → 对拍验证 → 性能收益 → 常见错误 → 检查点。

代码块的几种标签

  • 起点（你现在的代码）：教程开始时 llmgen 的快照（commit 91fac54），用来指出慢在哪。
  • lab 参考（3090 实测过）：直接读目标 lab 的源文件，一字不改。命名是 lab 的（dtype / device / alloc），照搬时要换成 llmgen 的（data_type / device_type / allocator）。
  • 改动对比：绿色行加、红色行删、其余是定位用的上下文。复制按钮只复制改完后的代码。
  • 新建文件 / 新增：按 llmgen 的命名写好的代码，可以整段复制。

性能数字的四种来源

  • lab 实测 消融实测 nsys 实测：目标 lab 在同一块 3090 上的记录。消融数字出自融合版 module-serving 关掉某个优化后的对比，方向和量级可以照搬，绝对值不行。
  • llmgen 起点实测：src/bench/40da889-dirty/run1.log。
  • 推算：由上面的数字算出来的，文中给出算式。没有在 llmgen 上实测过。
  • 你的实测：每页有一张可以直接填的表，数字存在浏览器本地，自动算提升倍数。
