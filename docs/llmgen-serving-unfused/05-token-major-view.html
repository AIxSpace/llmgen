阶段 1 · 去掉主机开销

token-major 零拷贝拆头

拆头不发 kernel，RoPE 从元数据读位置。

本步目标q / k / v 拆头不再发 kernel：[1, T, n·hd] 直接当成 [1, T, n, hd] 看。RoPE 改成 token-major 的 kernel，位置从元数据读。这一步做完先别跑，注意力和写 KV 要到第 06 步才配套。

原理

head-major 和 token-major

Linear 算出来的 q 是 [T, n·hd]：每个 token 一行，一行里 16 个头依次排开。这在内存里已经是 [T, n, hd] 了，reshape 不用动数据。

起点沿用了 PyTorch 的习惯，再 permute 成 [n, T, hd]（head-major），因为 F.scaled_dot_product_attention 要这个形状：

token-major
t0·h0t0·h1…t0·h15t1·h0t1·h1…t1·h15
head-major
h0·t0h0·t1…h1·t0h1·t1…h15·t0h15·t1
同一批数据的两种排法。Linear 的输出天然是上面那种。

每层为此发 4 个 permute kernel：q、k、v 各一个，注意力输出再转回来一个。28 层共 112 个 kernel，每个都把数据原样搬一遍，还各占一块激活内存。

注意力 kernel 其实不需要 head-major

自己写的注意力 kernel 想怎么寻址都行。token-major 下，第 t 个 token 第 h 个头的 q 在 q + (t·n + h)·hd，一样是连续的 128 个数。而 KV cache 是另一块内存，布局由我们自己定（第 06 步）。所以 permute 纯属多余。

token-major 还有一个好处：多条序列的 token 可以直接首尾相接排成一个 [T, …]（第 19 步的变长打包），不需要 padding。head-major 做不到这一点。

RoPE 要跟着改

RoPE kernel 靠下标算出“这是第几个 token、第几个头”。起点按 head-major 解下标：

src/backend/cuda/rope.cu 起点（你现在的代码）
template <typename T>
__global__ void apply_rope_kernel(
    T* __restrict__ out,
    const T* __restrict__ input,
    const float* __restrict__ cos_cache,
    const float* __restrict__ sin_cache,
    int64_t B, int64_t n_heads, int64_t seq_len,
    int64_t head_dim, int64_t rope_half, int64_t rope_dim,
    int64_t head_stride, int64_t batch_stride,
    int64_t cos_stride, int64_t start_pos
) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx >= B * n_heads * seq_len * head_dim) return;

    int i = idx % head_dim;
    int tmp = idx / head_dim;
    int s = tmp % seq_len;
    tmp /= seq_len;
    int h = tmp % n_heads;
    int b = tmp / n_heads;

    const T* row_in = input + b * batch_stride + h * head_stride + s * head_dim;
    T* row_out = out + b * batch_stride + h * head_stride + s * head_dim;
    int64_t pos = start_pos + s;

    if (i < rope_half) {
        float x0 = float(row_in[i]);
        float x1 = float(row_in[i + rope_half]);
        float c = cos_cache[pos * cos_stride + i];
        float si = sin_cache[pos * cos_stride + i];
        row_out[i] = T(x0 * c - x1 * si);
        row_out[i + rope_half] = T(x0 * si + x1 * c);
    } else if (i >= rope_dim) {
        row_out[i] = row_in[i];
    }
}

一个线程一个元素，每个线程做 4 次整数除法 / 取模来定位。位置是 start_pos + s，只适用于单条序列。

lab 的写法：一个 block 一个 token，一个 warp 一个头，32 个 lane 每人管 2 对元素。下标直接从 blockIdx / threadIdx 来，没有除法；位置查 positions[t]：

backend/cuda/rope.cu lab 参考（3090 实测过）
// ------------------------------------------------------------------
// rope(NEOX): 一个 block 一个 token, 一个 warp 一个头; lane 持有 i∈{lane, lane+32} 及其配对 i+64
// ------------------------------------------------------------------
__global__ void rope_kernel(bf16 *out, const bf16 *x, const float *cos_sin, const int *positions, int n_head) {
    const int HD = 128, HALF = 64;
    const int t = blockIdx.x, h = threadIdx.x >> 5, lane = threadIdx.x & 31;
    if (h >= n_head) return;
    const long base = ((long)t * n_head + h) * HD;
    const float *cs = cos_sin + (long)positions[t] * HD;
#pragma unroll
    for (int j = 0; j < 2; ++j) {
        const int i = lane + 32 * j;
        const float a = bf2f(x[base + i]), b = bf2f(x[base + i + HALF]), c = cs[i], s = cs[HALF + i];
        out[base + i] = f2bf(a * c - b * s);
        out[base + i + HALF] = f2bf(b * c + a * s);
    }
}

extern "C" void cuda_rope(cuda_bf16_t *out, const cuda_bf16_t *x, const float *cos_sin, const int *positions, int T, int n_head,
                        int hd) {
    if (T <= 0) return;
    if (hd != 128 || n_head > 32) {
        fprintf(stderr, "[serve] rope: 仅支持 head_dim=128 且 n_head<=32\n");
        return;
    }
    rope_kernel<<<T, n_head * 32, 0, g_cuda_stream>>>((bf16 *)out, (const bf16 *)x, cos_sin, positions, n_head);
}

3RoPE kernel

lab 的 kernel 读一张合并的 cos_sin 表；llmgen 的 cos 和 sin 是两张表，这里改成收两个指针，其余照搬：

src/backend/cuda/rope.cu（整个文件换掉） 新建文件
// rope.cu -- NEOX RoPE, token-major: x / out [T, n_head, 128]
// 位置从本步元数据的 positions[t] 读, 不再是"起点 + 序号"。
// cos / sin 是 llmgen 的两张 [max_seq, 128] f32 表(由 RopeCacheImpl<CPU> 算一次, 经拷贝代理常驻显存),
// 每行前后两半存同一个角度, 这里只读前半 i ∈ [0, 64)。
#include "cuda_common.cuh"

// 一个 block 一个 token, 一个 warp 一个头; lane 持有 i ∈ {lane, lane+32} 及其配对 i+64
__global__ void rope_kernel(bf16 *out, const bf16 *x, const float *cos_tab, const float *sin_tab, const int *positions, int n_head) {
    const int HD = 128, HALF = 64;
    const int t = blockIdx.x, h = threadIdx.x >> 5, lane = threadIdx.x & 31;
    if (h >= n_head) return;
    const long base = ((long)t * n_head + h) * HD;
    const long row = (long)positions[t] * HD;
#pragma unroll
    for (int j = 0; j < 2; ++j) {
        const int i = lane + 32 * j;
        const float a = bf2f(x[base + i]), b = bf2f(x[base + i + HALF]);
        const float c = cos_tab[row + i], s = sin_tab[row + i];
        out[base + i] = f2bf(a * c - b * s);
        out[base + i + HALF] = f2bf(b * c + a * s);
    }
}

extern "C" void cuda_rope(cuda_bf16_t *out, const cuda_bf16_t *x, const float *cos_tab, const float *sin_tab,
                          const int *positions, int T, int n_head, int hd) {
    if (T <= 0) return;
    if (hd != 128 || n_head > 32) {
        fprintf(stderr, "rope: 仅支持 head_dim=128 且 n_head<=32\n");
        return;
    }
    rope_kernel<<<T, n_head * 32, 0, g_cuda_stream>>>((bf16 *)out, (const bf16 *)x, cos_tab, sin_tab, positions, n_head);
}

/// src[0] = x [1, T, n_head, hd] bf16, src[1] = cos / src[2] = sin [max_seq, hd] f32(显存)

5QK-norm 不用改

RmsNormImpl<CUDA> 把输入看成 [rows, 权重长度]，rows = 元素数 / 权重长度。q_norm 的权重长度是 head_dim = 128，不管 q 是 [n, T, hd] 还是 [T, n, hd]，都是“每 128 个数归一化一次”，结果只是行的顺序不同。

做完这一步不能跑现在 q / k / v 是 token-major，但 appendKVFromTensor 和 paged_attention_kernel 还按 head-major 读，会算出错的结果（不会崩）。接着做第 06 步，两步合起来验证。
CPU 后端同理：backend/cpu/rope.zig 和 backend/cpu/attention.zig 也是 head-major 的，这两步要跟着换（见下面的“CPU 同步”），换完之后 CPU 和 CUDA 一起恢复可用。

对 llmgen 的预期

每步少 28 × 4 = 112 个 kernel。按第 02 步的账（每个 kernel 一次 launch + 一次 sync，单次约 12.9 + 16.5 µs），省下约 3.3 ms / 步 推算。permute kernel 本身搬的数据很小（decode 时一共几 KB），kernel 时间可以忽略。

prefill 时每个 permute 要搬 T × n × hd × 2 字节，512 token 时 q 是 2 MB、k / v 各 1 MB，每层 6 MB，28 层 168 MB 的无用搬运也没了。

这一步的数字要等第 06 步做完才能量。
